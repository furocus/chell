# Aの実装を読む：起動用文字列と二重ポインタ

この読み物では、Cで作るWindowsシェルから、**元の入力を残したまま、外部exeの起動に渡す文字列のコピーを作る処理**を一つ取り出します。困りごとから関数の設計、実装、成功時と失敗時の状態、利用後の片付けまで、同じ一例を追います。

必要なのは、変数・if・while・関数を見たことがある程度のCの知識です。ポインタ、文字列、メモリ確保の必要な説明は本文に含めています。他の課題、配布ソース、別の担当者の実装、リポジトリ内の別資料を開く必要はありません。

**目標は、`prepare_win32_line(raw, &line)` の `&` と、関数内の `*out_line = copy` が、何のために必要か説明できることです。** 実装を補完する課題ではなく、完成した一つの実装を読む教材です。環境構築、ビルド、実行、宿題は求めません。問いの答えも本文にあります。

最初に範囲を正確にしておきます。ここでいう「二重ポインタが必要」は、**成否を戻り値にし、確保した領域のアドレスを呼び出し元のポインタ変数へ書き込む、という今回の関数契約に必要**という意味です。同じ目的を、ポインタを戻り値にする別の関数で実現することもできます。文字列コピーそのものに二重ポインタが常に必須というわけではありません。

## 1. Aは、なぜ起動用のコピーを作るのか

今回作るシェルは、利用者から1行を受け取り、実行する処理を選び、終わったら次の入力へ戻ります。Aは、この繰り返しと外部exeの起動を担当します。

利用者が次の1行を入力したとします。

```text
tool.exe "hello world" ""
```

`tool.exe` は起動したいプログラムです。`"hello world"` は空白を含む一つの引数、`""` は長さ0の引数を表しています。この行全体を、ここでは `raw` と呼びます。

AがWindowsへ起動を依頼する関数は `CreateProcessW` です。この関数のコマンドライン引数には、**APIが内容を書き換えられる領域**を渡します。文字列リテラルや読み取り専用の文字列を、そのまま渡すことはできません。[公式資料：CreateProcessWのlpCommandLine](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)

シェル側では元の入力を保持したいので、起動用のコピーを別の領域に作ります。

```text
元の入力 raw ──→ [tool.exe "hello world" "" と終端]
                              内容をコピー
起動用   line ──→ [tool.exe "hello world" "" と終端]
```

最初は同じ内容でも、二つは別の領域です。起動用の方を変更しても、元の入力は変わりません。今回追うのは、このコピーを準備する `prepare_win32_line` という関数です。

exeの検索、引数分割、Ctrl+C、子の終了待ちまでを一度に実装する必要はありません。ここでは、「コピーを作って、その場所を呼び出し元へ知らせる」という一つの問題を解きます。

**ここで考える：** コピーが正しくできても、その場所が呼び出し元に伝わらなかったら、起動APIへ渡せるでしょうか。

渡せません。コピーの中身だけでなく、それがどこにあるかを表すポインタも必要です。この場所の受け渡しに二重ポインタを使います。

## 2. 三つのものを分けて読む

### 2.1 文字の領域と、場所を覚える変数

次の二行を見ます。

```c
const wchar_t raw[] = L"tool.exe 7";
wchar_t *line = NULL;
```

`wchar_t` はワイド文字を扱う型です。`L"..."` はその型の文字列を表します。WindowsのW版APIで使う文字列に合わせています。

`raw` は文字を並べた配列です。`const` により、この配列を書き換えないことを表します。文字列の最後には、本文の終わりを示す `L'\0'` が一つあります。表示する文字の `'0'` とは別です。

一方、`line` は文字配列ではなく、`wchar_t` のある場所を覚える**ポインタ変数**です。`NULL` は、今は有効な領域を指していない状態に使います。この宣言だけで、コピーを保存する文字の領域が確保されるわけではありません。

```text
rawの領域    [t][o][o][l][.][e][x][e][ ][7][\0]
lineという変数 [NULL]
```

宣言の `wchar_t *` は「wchar_tを指すポインタ型」です。式に現れる `*line` は「lineが指す先」を表します。同じ `*` でも、宣言の中か、値を扱う式の中かを分けて読みます。

### 2.2 mallocで作った領域は、ローカル変数とは別

実行中に必要な領域を確保するため、`malloc` を使います。引数はバイト数で、成功すると確保した領域のアドレス、失敗するとNULLを返します。[公式資料：mallocのParametersとReturn value](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/malloc?view=msvc-170)

```text
copyという変数 [領域Pのアドレス] ──→ [確保した文字の領域]
```

関数内の `copy` という変数と、mallocで作った領域は別です。関数が終わるとローカル変数 `copy` はなくなりますが、確保領域は自動では解放されません。`free` するまで利用できるので、関数をまたいで受け渡せます。

逆に、確保領域の場所を誰も覚えていなければ、利用も解放もできなくなります。これがメモリリークです。関数が終わる前に、領域のアドレスを呼び出し元へ伝える必要があります。

### 2.3 返す情報を二つに分ける

今回の関数宣言は次の形です。

```c
int prepare_win32_line(const wchar_t *raw, wchar_t **out_line);
```

戻り値の `int` は成功なら1、失敗なら0です。入力 `raw` は読む文字列、`out_line` は結果を書き込むための引数です。

| 情報 | 渡す経路 |
|---|---|
| コピーを準備できたか | 戻り値の1または0 |
| 成功したコピーはどこにあるか | `*out_line` へアドレスを代入 |

二つ目は文字列そのものを戻り値にするのではなく、呼び出し元が用意したポインタ変数へ書き込みます。そのため `out_line` の型が二重ポインタになります。

この段階では星の数を暗記せず、「書き換えたいものは文字なのか、ポインタ変数なのか」を意識してください。

## 3. 一重ポインタで書くと、どこで困るのか

先に、意図が届かない例を読みます。これは理由を見るための断片で、実行する完成コードではありません。

```c
void publish_wrong(wchar_t *out_line, wchar_t *copy)
{
    out_line = copy;
}
```

呼び出し元に `wchar_t *line = NULL;` があり、`publish_wrong(line, copy)` と呼んだとします。関数内で `out_line = copy` と代入すれば、呼び出し元のlineも変わるように見えるかもしれません。

しかしCでは、関数の引数へ**値のコピー**が渡されます。ポインタの場合も同じです。渡した値がNULLなら、関数の引数も最初はNULLですが、呼び出し元のlineと関数内のout_lineは別の変数です。[公式資料：Arguments](https://learn.microsoft.com/en-us/cpp/c-language/arguments?view=msvc-170)

```text
関数に入った直後
  呼び出し元 line     [NULL]
  関数の中   out_line [NULL]       ← 値をコピーした別の変数
  関数の中   copy     [領域P] ──→ [コピーした文字列]

out_line = copy; の後
  呼び出し元 line     [NULL]       ← 変わっていない
  関数の中   out_line [領域P] ──→ [コピーした文字列]
```

最後の代入が変えたのは、関数内のout_lineだけです。「値が同じだった」ことと、「同じ変数である」ことは違います。

では、一重ポインタのout_lineへ `*out_line = copy` と書けばよいのでしょうか。out_lineが `wchar_t *` なら、`*out_line` の型は `wchar_t` です。文字一つの置き場所であり、`wchar_t *` というアドレスを保存する場所ではありません。しかも、この例のout_lineはNULLから始まるため、指す先へ書き込んではいけません。

### 「ポインタなら変更できる」の対象を確かめる

既に存在する書き換え可能な文字配列の先頭を渡せば、その配列の文字は一重ポインタ経由で変更できます。これは間違いではありません。

今回変更したいのは、その文字配列の中身ではなく、**新しく作った領域を指すように、呼び出し元のポインタ変数を変更すること**です。相手に変更してほしい対象が一段違います。

**立ち止まって確認：** 今の呼び出しでは、lineという変数自体の場所を渡したでしょうか。

渡していません。渡したのはlineに入っていた値、つまりNULLだけです。関数からlineへ到達する手段がないことが、失敗の原因です。

## 4. ポインタ変数の場所を渡す

呼び出しを次の形にします。

```c
wchar_t *line = NULL;
int ok = prepare_win32_line(raw, &line);
```

`&` は変数のアドレスを得る演算子です。lineの型は `wchar_t *` なので、その変数の場所 `&line` の型は `wchar_t **` になります。文字列へのポインタを指すポインタ、という二段の関係です。

| 式 | 型 | 意味 |
|---|---|---|
| `line` | `wchar_t *` | コピー先の場所を覚える値。最初はNULL |
| `&line` | `wchar_t **` | ポインタ変数line自体の場所 |
| 関数内の `out_line` | `wchar_t **` | line自体の場所を覚えた値 |
| 関数内の `*out_line` | `wchar_t *` | 呼び出し元のlineという代入先 |
| 関数内の `**out_line` | `wchar_t` | コピー先の先頭の文字。コピー成功後なら参照可能 |

out_lineにも値のコピーが渡されます。ただし、その値は**呼び出し元のポインタ変数のアドレス**です。値渡しという規則を変えるのではなく、渡すアドレスの対象を変えます。

```text
関数の中                     呼び出し元
out_line [変数Mの場所] ──→ line [NULL]
copy     [領域Pの場所] ───────────────→ [コピーした文字列]

*out_line = copy; を行う

out_line [変数Mの場所] ──→ line [領域Pの場所] ──→ [コピーした文字列]
copy     [領域Pの場所] ───────────────────────→ [同じ領域]
```

「変数M」「領域P」は別の場所を区別するための名前です。実際のアドレス値を覚える必要はありません。

`*out_line = copy` では、out_lineが指す変数、つまりlineにcopyの値を代入しています。文字列の本文をコピーする行ではありません。本文をコピーする処理と、完成した領域のアドレスを渡す処理は別々です。

### 60分の地点で確認すること

`out_line = copy` と `*out_line = copy` の違いを、左辺の型と代入先で説明します。

- 前者は関数内のout_lineへの代入です。今回の宣言では `wchar_t **` と `wchar_t *` が一致しません。
- 後者の左辺は `wchar_t *` で、呼び出し元のlineを表します。copyと型が合い、意図した変数を更新できます。

キャストで型を無理に合わせる必要はありません。**何を指しているかが正しければ、代入先の型も自然に合います。**

ここで5分休憩します。戻ったら、同じ図を使って完成した関数を読みます。

## 5. 実装を処理の順番で読む

### 5.1 関数の約束

実装より先に、何を受け取り、どんな状態を返すか決めます。

- 入力は、呼び出し中に読み取り可能な、終端付きのワイド文字列です。NULLなら失敗とします。
- 出力先は、生存中で書き込み可能な `wchar_t *` 変数です。**初期値はNULLで、既存の所有領域を持たない変数を渡します。**
- 出力先のアドレス自体がNULLなら、何も書かず失敗とします。
- 有効な出力先があれば、最初に値をNULLへ戻します。失敗時もNULLの状態を保ちます。
- 成功時は元の入力とは別の領域を返し、呼び出し元がその領域を一度freeします。
- この例はシェルの短い入力、本文最大4,095要素を対象にします。巨大な入力を受ける汎用ライブラリではありません。

既存の領域を持つ変数を渡して最初にNULLへ戻すと、その場所を失ってしまいます。だから「新しい結果を受けるための空の変数」という約束が必要です。二重ポインタなら所有権を自動管理できる、という意味ではありません。

### 5.2 二つのNULLを区別する

```c
if (out_line == NULL) {
    return 0;
}
*out_line = NULL;
if (raw == NULL) {
    return 0;
}
```

`out_line == NULL` は、書き込む変数の場所自体がない状態です。ここでは `*out_line` に触れてはいけません。

一方、out_lineが有効なら `*out_line = NULL` で呼び出し元のlineを空にできます。`*out_line == NULL` は、変数はあるが、まだコピーの領域を指していない状態です。これは今回の正しい開始状態です。

この時点では領域の確保も、文字列のコピーも行っていません。ポインタ変数へNULLを保存しただけです。

### 5.3 必要な要素数を数える

```c
size_t length = 0;
while (length < 4096 && raw[length] != L'\0') {
    ++length;
}
if (length == 4096) {
    return 0;
}
```

`size_t` は、要素数やサイズに使う符号なし整数型です。終端が見つかるまで本文の要素数を数え、4,096要素を見ても終端がなければ失敗とします。`&&` は左が偽なら右を評価しないため、添字4,096は読みません。

ここでの上限は今回のシェルに合わせたものです。CreateProcessWそのものの上限と同じとは限りません。また、この確認で不正なポインタまで安全になるわけではありません。rawが有効な文字列を指すという約束は必要です。

`tool.exe 7` の本文は10要素です。終端も保存するため、確保に必要なのは11要素です。WindowsのUTF-16では見た目の1文字が複数の要素になる場合があるので、ここでの長さは表示上の文字数ではなく、wchar_tの要素数として読みます。

### 5.4 確保と本文のコピー

```c
wchar_t *copy = malloc((length + 1) * sizeof *copy);
if (copy == NULL) {
    return 0;
}
wmemcpy(copy, raw, length + 1);
```

`length + 1` は終端を含む要素数、`sizeof *copy` は1要素のバイト数です。mallocはバイト数を受け取るので、掛け合わせます。`sizeof *copy` は型のサイズを調べる式で、未確保の文字を読み出す操作ではありません。

今回は長さを4,095以下へ制限してから計算するので、Windows上でこの計算が巨大なサイズへあふれることはありません。上限を取り除いて汎用化するなら、サイズのあふれの確認も必要になります。

`wmemcpy` の最後の引数は、バイト数ではなくコピーするワイド文字の要素数です。`length + 1` とすることで本文と終端を一緒にコピーします。入力とコピー先は別の領域なので、重なりません。[公式資料：wmemcpyのParametersとRemarks](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/memcpy-wmemcpy?view=msvc-170)

この三行を終えても、呼び出し元のlineはまだNULLです。新しい領域を指しているのは、関数内のcopyだけです。

### 5.5 場所を渡し、成功を返す

```c
*out_line = copy;
return 1;
```

最初の行で、呼び出し元のlineへ新しい領域のアドレスが入ります。次の行で、戻り値として成功を知らせます。

この時点から、領域を解放する責任は呼び出し元へ渡します。ここでfreeしてから成功を返すと、呼び出し元が受け取るのは解放済み領域を指すアドレスになってしまいます。

「本文のコピー」はwmemcpy、「場所の受け渡し」は `*out_line = copy`、「成否の通知」は `return 1` です。この三つを分けて読めれば、実装の中心を理解できています。

## 6. 一つのファイルとして最初から読む

必要なヘッダー、コピー関数、呼び出し元を含む全コードです。別のソースやヘッダーの内容を知らなくても読めます。コードはTODOのない完成例で、実際の子プロセスは起動しません。コピーが作られ、変更でき、元の入力が残るところを見ます。

```c
#include <stdio.h>
#include <stdlib.h>
#include <wchar.h>

int prepare_win32_line(const wchar_t *raw, wchar_t **out_line)
{
    if (out_line == NULL) {
        return 0;
    }
    *out_line = NULL;
    if (raw == NULL) {
        return 0;
    }

    size_t length = 0;
    while (length < 4096 && raw[length] != L'\0') {
        ++length;
    }
    if (length == 4096) {
        return 0;
    }

    wchar_t *copy = malloc((length + 1) * sizeof *copy);
    if (copy == NULL) {
        return 0;
    }
    wmemcpy(copy, raw, length + 1);

    *out_line = copy;
    return 1;
}

int main(void)
{
    const wchar_t raw[] = L"tool.exe \"hello world\" \"\"";
    wchar_t *line = NULL;

    int ok = prepare_win32_line(raw, &line);
    if (!ok) {
        wprintf(L"copy failed\n");
        return 1;
    }

    wprintf(L"before: %ls\n", line);
    line[0] = L'T';
    wprintf(L"after : %ls\n", line);
    wprintf(L"source: %ls\n", raw);

    free(line);
    line = NULL;
    wprintf(L"released: %d\n", line == NULL);
    return 0;
}
```

文字列の中の `\"` は、Cソースで引用符を文字として含めるための表記です。実行時の文字列に、この表記のためのバックスラッシュが残るわけではありません。ここでは引数を分割していません。

成功時の出力は次のとおりです。

```text
before: tool.exe "hello world" ""
after : Tool.exe "hello world" ""
source: tool.exe "hello world" ""
released: 1
```

先頭を大文字にするのは、書き換え可能で独立した領域かを観察するためです。実際の起動前にコマンド名を変更する機能を追加した、という意味ではありません。

### 呼び出し前から片付けまでの状態

| 止まる場所 | 呼び出し元のline | 関数内で起きたこと |
|---|---|---|
| 呼び出し直前 | NULL | まだコピーはない |
| 関数へ入った直後 | NULL | out_lineがlineという変数を指す |
| malloc成功直後 | NULL | copyだけが新しい領域を指す |
| wmemcpyの直後 | NULL | 新しい領域の本文と終端が完成した |
| `*out_line = copy` の直後 | 新しい領域を指す | 呼び出し元へ場所が届いた |
| 成功して戻った直後 | 新しい領域を指す | ローカル変数copyは消えても、領域は残る |
| freeとNULL代入の後 | NULL | 領域を解放し、変数も空へ戻した |

この表を使い、`line[0] = L'T'` の前に何が済んでいる必要があるか考えてください。確保、終端までのコピー、呼び出し元へのアドレスの保存、成功判定です。NULLのまま書き込む処理にはなっていません。

## 7. 失敗と後片付けを同じ図で読む

### 7.1 途中で戻ったとき

通常の呼び出しは、lineがNULLの状態から始めます。

| 条件 | 戻り値 | 呼び出し後 |
|---|---|---|
| 出力先のアドレス自体がNULL | 0 | 出力先がない。間接参照も確保もしない |
| 入力がNULL、有効な出力先あり | 0 | lineはNULL。確保なし |
| 本文が4,096要素以上 | 0 | lineはNULL。確保なし |
| mallocがNULLを返す | 0 | lineはNULL。今回解放する領域なし |
| 本文0〜4,095要素、確保成功 | 1 | lineがコピーを指す。呼び出し元が一度free |

すべての失敗を0で返すため、戻り値だけでは失敗の詳細までは分かりません。ここは今回の小さな関数の制限です。詳細が必要なら、失敗の分類を戻す型へ変えるなど、関数の契約を広げます。今回の主題であるアドレスの受け渡しとは、別の判断です。

mallocの失敗は、戻り値がNULLかで判断します。このCの確保処理でGetLastErrorを読んでも、今回の失敗理由を正しく取得したことにはなりません。Win32の失敗と混同しないでください。

空文字列は成功できます。本文長0でも終端1要素の領域を確保するからです。シェルが空行を実行対象から外す判断は別の工程です。文字列を複製する関数へ、コマンドの妥当性判定まで持たせません。

### 7.2 確保した後に失敗処理を追加したら

現在の関数では、malloc成功後にwmemcpyでコピーし、そのまま領域を引き渡します。入力は有効、コピー先は十分な容量、領域は非重複という条件を満たしています。

将来、確保成功後に「別のAPIを呼び、そのAPIが失敗する」処理を追加した場合はどうでしょう。その時点では、まだ呼び出し元へ渡していないcopyを関数内でfreeしてから失敗を返す必要があります。

誰がその領域の後片付けを担当しているかは、成功時だけでなく途中の時点でも追います。今のコードが短いからといって、将来どんな処理を追加しても後片付け不要とは限りません。

### 7.3 freeするのは、何のアドレスか

使い終わった呼び出し元は、次を行います。

```c
free(line);
line = NULL;
```

lineが持つのは、mallocが返した領域の先頭アドレスです。`&line` は呼び出し元の変数自体のアドレスなので、`free(&line)` とはしません。元のrawも、今回mallocで確保した領域ではないのでfreeしません。[公式資料：freeのRemarks](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/free?view=msvc-170)

領域の解放と、変数へのNULL代入は別の処理です。freeした後の領域へアクセスしてはいけません。直後にlineをNULLへ戻して、呼び出し元の状態も空にします。ほかの変数が同じ領域を指していた場合、その別の変数まで自動でNULLになるわけではありません。

今回、NULLへのリセットは呼び出し元で直接書いています。これも別関数へ任せて呼び出し元の変数を変更したいなら、その変数の場所を渡すことになります。新しい関数を書く課題は増やさず、「ここでも変更対象から渡すものが決まる」と結び付けてください。

## 8. Aの起動処理へ戻して考える

コピー関数だけを練習して終わらず、実際の処理のどこに置くかを見ます。

```text
元の入力を受け取る
    ↓
起動するexeの絶対パスを決める
    ↓
prepare_win32_line(raw, &line)
    ↓ 成功した場合だけ
CreateProcessWへ、絶対パスとlineを渡す
    ↓ 成功・失敗の両方で
起動用コピーをfreeし、lineをNULLへ戻す
    ↓ 起動が成功した場合だけ
子の終了待ち・終了コードの取得・HANDLEの後片付けへ進む
```

CreateProcessWの関係する引数だけを表へ抜き出します。起動関数全体を新しく実装する必要はありません。

| 引数 | Aが渡すもの | コピー関数との関係 |
|---|---|---|
| `lpApplicationName` | 解決済みexeの絶対パス | 何を起動するかを明示する。今回の関数では検索しない |
| `lpCommandLine` | line | 書き換え可能なコピーを渡す |
| `lpStartupInfo` | 起動設定の構造体のアドレス | 設定を読むための引数。今回のコピーとは別 |
| `lpProcessInformation` | 起動結果を受け取る構造体のアドレス | HANDLEなどを受け取る。今回の文字列領域とは別 |

実行先をlpApplicationNameで明示しても、コマンドライン側には通常、先頭のプログラム名も含めます。本文のrawは、`tool.exe "hello world" ""` のような、名前を含む元の1行です。分割済みの引数を単純に空白でつなぎ直すと引用符や空引数の表記を失うため、今回の処理は元の行をそのままコピーします。[公式資料：CreateProcessWのlpApplicationNameとlpCommandLine](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)

起動用のコピーは、CreateProcessWの呼び出しが戻るまで保持します。呼び出しが戻れば、親のこのコピーを子の実行中ずっと保持する必要はなく、成功した場合も失敗した場合も解放する設計にできます。起動に失敗した場合は、直後にGetLastErrorの値を保存してから後片付けを行います。

ただし、文字列をfreeしても、子の終了待ちやHANDLEの解放が済むわけではありません。文字列の領域とOSのHANDLEは異なる資源です。この読み物で実装を追ったのは、起動直前の文字列の準備と受け渡しだけです。

### 二つの呼び出しで、渡すものが違う

コピー関数には `&line` を渡します。新しい領域を関数の中で確保し、呼び出し元のポインタ変数lineを書き換えてほしいからです。

起動APIにはlineを渡します。既に用意された文字列の領域へアクセスしてほしいからです。そこでは、ポインタ変数line自体のアドレスを渡す必要はありません。

| 相手にしてほしいこと | 渡すもの |
|---|---|
| 呼び出し元のポインタ変数へ、確保先を保存する | その変数のアドレス `&line` |
| 用意した文字列を利用・変更する | 文字列のアドレスline |

### 二重ポインタ以外の設計も選べる

ポインタを戻り値にする関数なら、呼び出し元は `line = 別設計のコピー関数(raw)` と書けます。成功は非NULL、失敗はNULLで表す設計も可能です。今回のように成功か失敗だけを返すなら、それも十分に成立します。

今回二重ポインタを使ったのは、「戻り値は成否、領域のアドレスは出力引数」という返し方を選んだからです。**この返し方のまま、呼び出し元のポインタ変数へ書き込むには二重ポインタが必要**です。二重ポインタの方が常に優れている、と覚える必要はありません。

呼び出し元が固定配列を用意して、その文字の領域へコピーする別設計もできます。その場合は、一重ポインタと容量を渡す形などになります。今回は「関数が領域を作り、その場所を渡す設計」を理解するために、一例を最後まで追いました。

## 9. 最後の10分：少し違う条件を考える

別の実装は書きません。次を予想してから、下の答えと照らし合わせてください。

1. 呼び出し元の変数名をbufferへ変えたら、呼び出しと関数内の代入はどう対応するか。
2. out_lineが非NULLで、*out_lineがNULLという状態は、失敗なのか。
3. mallocとwmemcpyが成功しても、`*out_line = copy` を削除したらどうなるか。
4. rawが空文字列なら、何要素分を確保するか。
5. 本文が4,095要素と4,096要素の場合で結果はどう違うか。
6. `*out_line = copy` の後に `free(copy)` してから戻ると、何が壊れるか。
7. lineが前のコピーを所有したまま、もう一度 `prepare_win32_line(raw, &line)` を呼ぶと何が問題か。
8. 起動APIへ `&line` を渡せば、より確実に文字列を渡せるだろうか。

<details>
<summary>答えと理由</summary>

1. `prepare_win32_line(raw, &buffer)` と呼びます。関数内の `*out_line = copy` は、今度はbufferへの代入になります。引数名を呼び出し元と一致させる必要はありません。渡したアドレスがどの変数を指すかで決まります。
2. 失敗ではありません。書き込む変数はあり、値は空という、今回の正常な開始状態です。
3. 呼び出し元のlineはNULLのままです。関数内のcopyがなくなると領域の場所を失い、コピーを使えず、メモリリークも起きます。
4. 終端の1要素分を確保します。確保に成功すれば1を返します。
5. 4,095なら終端を含む4,096要素を確保して成功できます。4,096なら長すぎる入力として0を返し、確保しません。
6. 呼び出し元が解放済み領域のアドレスを受け取ります。その領域をAPIに渡すことも、もう一度freeすることも正しくありません。
7. 関数の約束に違反します。最初の `*out_line = NULL` で前の領域の場所を失います。呼び出し元で前の領域をfreeし、lineをNULLへ戻してから次のコピーを受け取ります。
8. 渡せません。起動APIに必要なのは文字列のアドレスlineです。`&line` は変数自体のアドレスなので、型も意味も違います。星を増やせば確実になるわけではありません。

</details>

最後に、この一文の空欄を自分の言葉で埋めます。

> 今回は、戻り値で＿＿を返し、関数内で確保した＿＿を、呼び出し元の＿＿へ保存したい。そのため＿＿を渡し、関数内で＿＿へ代入する。

答えの一例は、「成否」「領域のアドレス」「ポインタ変数」「その変数のアドレス」「`*out_line`」です。これをlineとout_lineの図に対応させて説明できれば、この読み物の到達点です。
