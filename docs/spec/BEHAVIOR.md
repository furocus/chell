# Chell 動作仕様（準備版）

## 1. 対象環境と完成範囲

Windows x64、C17、Win32のUnicode/W版APIを基本にします。実際の固定ツール版と起動手順は、リポジトリのconfig/toolchain.json、CMake、scripts、READMEを優先します。シェル内はUTF-16のwchar_t文字列を受け渡し、外部ファイルへの文字出力はUTF-8を方針とします。

1回の入力に1コマンドを同期実行します。外部exeの終了を待ってから次の入力を受け付けます。子プログラムの入力・出力は同じコンソールを使います。

対象外: パイプ、リダイレクト構文、条件付き実行、バックグラウンド・ジョブ管理、環境変数やワイルドカードの展開、独自スクリプト、bat/cmdの自動委譲、独自履歴・Tab補完・行編集、複数行貼り付けの編集画面、子の強制終了。対象外機能はhelpにも実装済みとして記載しません。

## 2. 入力規則

| 項目 | 仕様 |
|---|---|
| 入力元 | 対話コンソール。シェル自身のファイル・パイプ入力は未対応エラー |
| 長さ | 終端を含め4,096 UTF-16コード単位。本文は最大4,095単位 |
| 引数 | コマンド名を含め最大64個 |
| 改行 | 1行分のCR/LFを除いて終端する。改行と終端は本文上限へ数えない |
| 空行・空白・タブだけ | 実行せず次の入力へ。直前の終了コードを維持 |
| 長すぎる行 | 部分実行しない。Bが残りを行末まで破棄し、エラー後に次の行へ |
| 入力終了 | Ctrl+Zを押してEnter（U+001Aだけの行）でEOF。直前の終了コードで終了 |
| 入力中断 | 入力途中のCtrl+C/対象の制御イベントで蓄積行を破棄して再入力 |
| 文字数 | UTF-16単位と表示上の文字数を同一視しない |

上限ちょうどの行でも、改行がbufferへ収まらないという理由だけで超過にしません。余分な本文があるかをBが区別します。複数行の貼り付けは1行ずつ通常処理し、超過の破棄で次の行まで捨てないようにします。中断と超過が重なった際の優先順位・残入力の扱いもD02の確認対象です。

コンソールモードを変更する場合は、取得した元のモードと復元の責任をA/B/Eで決め、正常終了・失敗終了の両方で確認します。Ctrl+Z単独行からEOFへの変換はChellの規則であり、ReadConsoleWがファイル入力と同じEOFを自動提供するとは仮定しません。

プロンプトは「現在位置 + > + 空白」をstdoutへ出す案です（例: C:\work> ）。出力成功を確認してから入力します。

## 3. 解析規則

空白・タブでコマンド名と引数を分けます。ダブルクォート内の空白を保持し、空の引数も保持します。先頭の空白・タブは除きます。

Cは未対応構文と引用符の不整合を検査した後、CommandLineToArgvWで引数を得ます。先頭空白の除去と空入力判定は、そのAPIを呼ぶ前に行います。コマンド名が空なら拒否します。

引用符外の | & < > は拒否します。引用符内では普通の引数文字として保持します。シングルクォートは引用規則を持たない通常文字、%NAME%も展開しない通常文字列です。

入力上限は先頭空白除去前に検査します。raw_lineは先頭空白を除いた入力のコピーです。引数表記の空白・引用符・バックスラッシュを保持します。外部exeへ渡す行をargvから作り直しません。引用符の前のバックスラッシュとargv[0]の詳細な期待値はD06で固定します（9節に観測例）。

| 入力 | 期待する解析・扱い |
|---|---|
| echo hello | argc=2、argv[1]=hello |
| echo "hello world" | argc=2、argv[1]=hello world |
| echo "" | argc=2、argv[1]は長さ0 |
| echo | argc=1 |
| `echo "a\|b"` | 文字列a\|bを引数として保持 |
| `echo a\|b` | 未対応演算子として拒否 |
| echo "hello | 閉じない引用符として拒否 |
| "" arg | 空のコマンド名として拒否 |
| 空白だけ | PARSE_EMPTY、Commandは空 |

公式APIの性質とChellの拒否規則を混同しません。独自検査とAPIの解釈が食い違うケースをテスト表へ追加します。[CommandLineToArgvW公式資料](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-commandlinetoargvw)

## 4. 組み込みコマンド

コマンド名は大文字・小文字を区別せず完全一致です。引数の文字列やパスを一律に大文字・小文字変換しません。

| コマンド | 正常動作 | 引数の失敗 |
|---|---|---|
| cd [path] | 省略時は現在位置表示。指定時はシェル自身の現在位置を変更 | 2引数以上は失敗。変更失敗で現在位置を変えない |
| pwd | 現在位置を表示 | 引数があれば失敗 |
| dir [path] | 現在位置か指定ディレクトリの直下の名前と種類を表示 | 2引数以上・通常ファイル指定・列挙失敗はエラー |
| echo [args...] | 解析済み引数を空白1つで連結し、最後に改行 | 引数なしも正常で改行だけ |
| help | 6コマンドと使い方を表示 | 引数があれば失敗 |
| exit | exit_requestedをTRUEにし、結果0を返す | 引数があれば失敗し、終了要求を立てない |

dirは再帰・ソート・ワイルドカード指定・追加オプションを持たず、.と..は表示しません。空ディレクトリは成功で項目出力なし、順序は保証しません。表示案は各行を [DIR] 名前 / [FILE] 名前とします。途中で列挙や表示に失敗したら、それまでの出力を巻き戻さず失敗として報告します。cd "" / dir "" は省略と区別し、引数誤りにする案です。

成功コードは0、組み込みの引数・処理失敗は1です。既知コマンドの引数エラーでもhandled=TRUEを返します。exitはプロセスを直接終了せず、Aが解放と終了処理を行います。

## 5. 外部exe

組み込みの両判定がhandled=FALSEなら外部exeを探します。

- パス区切り（\または/）やドライブ指定（:）のある名前は明示パスとして解決する。
- 単純な名前はPATHの記載順で検索する。拡張子なしでは.exeを補う。
- カレントディレクトリを暗黙検索しない。現在位置のexeは./tool.exe等の明示パスで指定する。
- PATH未設定・空文字列なら候補なし。空項目は現在位置として扱わない。PATH項目全体を囲む1組の引用符を除く。
- 相対PATH項目は現在位置に依存するため、草案では絶対パスの項目のみ使う案とする。意図せずカレント検索が混ざらないようA/Eで確認する。
- .bat/.cmd等は自動でcmd.exeへ委譲しない。
- 解決したexeのパスと、raw_lineの書き換え可能なコピーを起動APIへ渡す。
- 子には親の環境と現在位置を引き継ぐ。起動・待機・終了コード取得を別々に確認する。

Chellが解析したargvと、子がraw_lineから自分で解析したargvは常に同じとは限りません。子は独自の解析器を使うこともあります。MSVC製の自作child_probe.exeで、日本語・空引数・引用符・バックスラッシュの引き継ぎを別途確認します。

exeを明示する理由と書き換え可能な行の条件は、[CreateProcessW公式資料](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)を参照します。PATHのみを検索する方針はChell固有の仕様です。

## 6. 終了コードと失敗時の復帰

ShellStateのlast_exit_codeの初期値は0です。

| 結果 | last_exit_code / 次の動作 |
|---|---|
| 組み込み完了 | 返されたexit_codeを保持 |
| 子の終了確認済み | 子のexit_codeを保持。非0でもAPI失敗と区別 |
| 空行・入力中断 | 変更せず次の入力へ |
| 不正構文・上限超過・起動失敗 | 1にし、報告して次の入力へ |
| exit成功 | Commandを解放し、0で終了 |
| EOF | 直前のコードで終了 |
| LINE_ERROR | 報告して1で終了する案（D03）。エラーを出し続けない |
| プロンプト・通常出力・診断出力の失敗 | 再帰報告せず1で終了する案（D03）。組み込みはoutput_failed=TRUEで伝える |
| 起動後、終了待ち・終了取得に失敗 | 新たなコマンドを重ねず、報告・後片付けして非0終了する案（D04） |

D04では子の終了を確認したと偽りません。HANDLEを閉じても子の強制終了を意味しません。子の強制終了は本体の対象範囲へ自動追加しません。

組み込みは処理の文脈と保存済みWin32エラーをB経由で報告し、Aは同じエラーを二重表示しません。processは画面表示せず結果をAへ返し、AがBを呼びます。エラー表示自体の失敗で再帰しません。Chell独自の構文・引数エラーはconsole_write_error、保存済みWin32エラーはconsole_report_errorを使い、どちらも戻り値を確認します。これは重複表示を避けるための準備版の責任分担です。

## 7. 中断

Ctrl+C/対象のCtrl+Breakでは、親シェルを存続させます。入力中と子の実行中を別ケースで検証します。中断に対応する子が終了したことを確認してから次の入力へ戻ります。中断を無視する子の強制終了は対象外です。

通知イベントをconsole_read_lineへ渡すだけでは、ブロック中の読み取りを解除する実装にはなりません。A/B/Eで入力モード、読み取り解除方法、実行中ハンドラーと解放の同期を決め、通常コンソールで確認します。詳細はD02として未固定です。組み込み処理中の中断は、ハンドラーから強制的に抜けず資源を片付けます。通常完了として扱うか中断結果へ変換するかもD02で決めます。ウィンドウを閉じる操作やログオフは、Ctrl+Cと同じ存続保証には含めません。

[SetConsoleCtrlHandler公式資料](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler) / [ReadConsole公式資料](https://learn.microsoft.com/en-us/windows/console/readconsole)

## 9. D06を決めるためのAPI観測例

2026-11-17、このWindows端末でCommandLineToArgvWを直接呼び、戻った文字列を確認しました。下の入力・値はCリテラルではなく、実際の文字をそのまま記載しています。これはOS APIの観測であり、Chellの検査実装が合格した記録ではありません。

| 実際の入力 | APIが返したargv | Chellでの扱い案 |
|---|---|---|
| `echo ""` | `echo` / 空文字列 | 受理 |
| `echo "a\"b"` | `echo` / `a"b` | 受理。奇数のバックスラッシュに続く引用符は文字 |
| `echo "a\\" b` | `echo` / `a\` / `b` | 受理。偶数のバックスラッシュに続く引用符は境界 |
| `echo a\"b` | `echo` / `a"b` | 受理。引用符を単純に数えない |
| `"C:\work dir\probe.exe" ""` | `C:\work dir\probe.exe` / 空文字列 | 受理。コマンド名全体を囲む |
| `"" arg` | 空文字列 / `arg` | 空のコマンド名として拒否 |
| `echo "open` | `echo` / `open` | Chellは閉じない引用符として拒否 |
| `echo "a""b"` | `echo` / `a"b` | 隣接引用符の検査規則を要合意 |
| `ec"ho" x` | `ec"ho"` / `x` | コマンド名内の部分引用は拒否する案 |

通常引数の検査では、引用符直前の連続バックスラッシュの偶奇を見ます。コマンド名は同じ規則と断定しません。隣接・連続引用符、演算子とエスケープ引用符の混在も期待値を並べ、検査器とAPIが同じ範囲を受理することをC/A/Eで確認します。Microsoft Cランタイムの[コマンド行解析規則](https://learn.microsoft.com/en-us/cpp/c-language/parsing-c-command-line-arguments?view=msvc-170)とも完全一致を前提にしません。

## 10. 確認記録の書き方

各ACは「未実施 / 合格 / 不合格 / D02等の合意待ち」を分けて記録します。最低限、確認日・コミット・構成（Debug/Release）・実行環境・入力・期待値・実測・確認者を残します。現在のAC01〜AC08はすべて本体未検証です。

例（期待値のみ、実測ではありません）:

| 入力・操作 | 期待値 | どこを確認するか |
|---|---|---|
| `pwd extra` → `echo next` | 引数エラーの後、nextと改行 | handled=TRUEのまま復帰 |
| `echo ""` | 改行だけ | 解析結果はargc=2（引数なしと区別） |
| 本文4,095単位 → 本文4,096単位 → `echo next` | 上限内だけ受理、超過行は実行せず、nextを処理 | 終端・改行・次行への混入 |
| 子が7で終了 → 空行 → EOF | 最終終了コード7 | API成功と子の失敗を区別 |
| 子が7で終了 → `exit` | 最終終了コード0 | 明示exitの仕様 |
| 子の終了待ち失敗をテスト用差し替えで再現 | 後片付けして1、新しい入力を受け付けない | D04の異常経路 |

出力失敗や待機失敗は手動入力で偶然起きるのを待たず、テスト用ラッパーで失敗を返せる接点を設けて確認します。テストのためだけの動作切替を製品のコマンドへ追加しません。
