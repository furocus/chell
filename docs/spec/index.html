何を作るか

Windowsの対話コンソールで1行を受け取り、組み込みコマンドか外部exeを同期実行し、次の入力へ戻るシェルです。独自のターミナル画面は作りません。

対象: cd / pwd / dir / echo / help / exit、外部exe、PATH検索、日本語、引数解析、エラー後の復帰、中断、メモリとHANDLEの解放。詳しい境界は動作仕様を参照してください。

全員で共有する処理の図

矢印は関数呼び出し・処理順です。Issueをこの順にすべて完了させる、という意味ではありません。

表示失敗をAへ伝えるoutput_failedはD03/D05の追加案です。入力・表示の致命的失敗は1で終了する案、外部exeの起動前の失敗は1で通常復帰する案です。

Chell 動作仕様（準備版）

入口 / 公開API / 担当別ガイド

状態: レビュー用草案。過去の設計を基準に整理した仕様で、実装・検証の完了を表しません。未合意の変更は入口のD01〜D06を参照してください。

1. 対象環境と完成範囲

Windows x64、C17、Win32のUnicode/W版APIを基本にします。実際の固定ツール版と起動手順は、リポジトリのconfig/toolchain.json、CMake、scripts、READMEを優先します。シェル内はUTF-16のwchar_t文字列を受け渡し、外部ファイルへの文字出力はUTF-8を方針とします。

1回の入力に1コマンドを同期実行します。外部exeの終了を待ってから次の入力を受け付けます。子プログラムの入力・出力は同じコンソールを使います。

対象外: パイプ、リダイレクト構文、条件付き実行、バックグラウンド・ジョブ管理、環境変数やワイルドカードの展開、独自スクリプト、bat/cmdの自動委譲、独自履歴・Tab補完・行編集、複数行貼り付けの編集画面、子の強制終了。対象外機能はhelpにも実装済みとして記載しません。

2. 入力規則

項目 仕様
入力元 対話コンソール。シェル自身のファイル・パイプ入力は未対応エラー
長さ 終端を含め4,096 UTF-16コード単位。本文は最大4,095単位
引数 コマンド名を含め最大64個
改行 1行分のCR/LFを除いて終端する。改行と終端は本文上限へ数えない
空行・空白・タブだけ 実行せず次の入力へ。直前の終了コードを維持
長すぎる行 部分実行しない。Bが残りを行末まで破棄し、エラー後に次の行へ
入力終了 Ctrl+Zを押してEnter（U+001Aだけの行）でEOF。直前の終了コードで終了
入力中断 入力途中のCtrl+C/対象の制御イベントで蓄積行を破棄して再入力
文字数 UTF-16単位と表示上の文字数を同一視しない

上限ちょうどの行でも、改行がbufferへ収まらないという理由だけで超過にしません。余分な本文があるかをBが区別します。複数行の貼り付けは1行ずつ通常処理し、超過の破棄で次の行まで捨てないようにします。中断と超過が重なった際の優先順位・残入力の扱いもD02の確認対象です。

コンソールモードを変更する場合は、取得した元のモードと復元の責任をA/B/Eで決め、正常終了・失敗終了の両方で確認します。Ctrl+Z単独行からEOFへの変換はChellの規則であり、ReadConsoleWがファイル入力と同じEOFを自動提供するとは仮定しません。

プロンプトは「現在位置 + > + 空白」をstdoutへ出す案です（例: C:\work> ）。出力成功を確認してから入力します。

3. 解析規則

空白・タブでコマンド名と引数を分けます。ダブルクォート内の空白を保持し、空の引数も保持します。先頭の空白・タブは除きます。

Cは未対応構文と引用符の不整合を検査した後、CommandLineToArgvWで引数を得ます。先頭空白の除去と空入力判定は、そのAPIを呼ぶ前に行います。コマンド名が空なら拒否します。

引用符外の | & < > は拒否します。引用符内では普通の引数文字として保持します。シングルクォートは引用規則を持たない通常文字、%NAME%も展開しない通常文字列です。

入力上限は先頭空白除去前に検査します。raw_lineは先頭空白を除いた入力のコピーです。引数表記の空白・引用符・バックスラッシュを保持します。外部exeへ渡す行をargvから作り直しません。引用符の前のバックスラッシュとargv[0]の詳細な期待値はD06で固定します（9節に観測例）。

入力 期待する解析・扱い
echo hello argc=2、argv[1]=hello
echo "hello world" argc=2、argv[1]=hello world
echo "" argc=2、argv[1]は長さ0
echo argc=1
echo "a|b" 文字列a|bを引数として保持
echo a|b 未対応演算子として拒否
echo "hello 閉じない引用符として拒否
"" arg 空のコマンド名として拒否
空白だけ PARSE_EMPTY、Commandは空

公式APIの性質とChellの拒否規則を混同しません。独自検査とAPIの解釈が食い違うケースをテスト表へ追加します。CommandLineToArgvW公式資料

4. 組み込みコマンド

コマンド名は大文字・小文字を区別せず完全一致です。引数の文字列やパスを一律に大文字・小文字変換しません。

コマンド 正常動作 引数の失敗
cd [path] 省略時は現在位置表示。指定時はシェル自身の現在位置を変更 2引数以上は失敗。変更失敗で現在位置を変えない
pwd 現在位置を表示 引数があれば失敗
dir [path] 現在位置か指定ディレクトリの直下の名前と種類を表示 2引数以上・通常ファイル指定・列挙失敗はエラー
echo [args...] 解析済み引数を空白1つで連結し、最後に改行 引数なしも正常で改行だけ
help 6コマンドと使い方を表示 引数があれば失敗
exit exit_requestedをTRUEにし、結果0を返す 引数があれば失敗し、終了要求を立てない

dirは再帰・ソート・ワイルドカード指定・追加オプションを持たず、.と..は表示しません。空ディレクトリは成功で項目出力なし、順序は保証しません。表示案は各行を [DIR] 名前 / [FILE] 名前とします。途中で列挙や表示に失敗したら、それまでの出力を巻き戻さず失敗として報告します。cd "" / dir "" は省略と区別し、引数誤りにする案です。

成功コードは0、組み込みの引数・処理失敗は1です。既知コマンドの引数エラーでもhandled=TRUEを返します。exitはプロセスを直接終了せず、Aが解放と終了処理を行います。

5. 外部exe

組み込みの両判定がhandled=FALSEなら外部exeを探します。

  • パス区切り（\または/）やドライブ指定（:）のある名前は明示パスとして解決する。
  • 単純な名前はPATHの記載順で検索する。拡張子なしでは.exeを補う。
  • カレントディレクトリを暗黙検索しない。現在位置のexeは./tool.exe等の明示パスで指定する。
  • PATH未設定・空文字列なら候補なし。空項目は現在位置として扱わない。PATH項目全体を囲む1組の引用符を除く。
  • 相対PATH項目は現在位置に依存するため、草案では絶対パスの項目のみ使う案とする。意図せずカレント検索が混ざらないようA/Eで確認する。
  • .bat/.cmd等は自動でcmd.exeへ委譲しない。
  • 解決したexeのパスと、raw_lineの書き換え可能なコピーを起動APIへ渡す。
  • 子には親の環境と現在位置を引き継ぐ。起動・待機・終了コード取得を別々に確認する。

Chellが解析したargvと、子がraw_lineから自分で解析したargvは常に同じとは限りません。子は独自の解析器を使うこともあります。MSVC製の自作child_probe.exeで、日本語・空引数・引用符・バックスラッシュの引き継ぎを別途確認します。

exeを明示する理由と書き換え可能な行の条件は、CreateProcessW公式資料を参照します。PATHのみを検索する方針はChell固有の仕様です。

6. 終了コードと失敗時の復帰

ShellStateのlast_exit_codeの初期値は0です。

結果 last_exit_code / 次の動作
組み込み完了 返されたexit_codeを保持
子の終了確認済み 子のexit_codeを保持。非0でもAPI失敗と区別
空行・入力中断 変更せず次の入力へ
不正構文・上限超過・起動失敗 1にし、報告して次の入力へ
exit成功 Commandを解放し、0で終了
EOF 直前のコードで終了
LINE_ERROR 報告して1で終了する案（D03）。エラーを出し続けない
プロンプト・通常出力・診断出力の失敗 再帰報告せず1で終了する案（D03）。組み込みはoutput_failed=TRUEで伝える
起動後、終了待ち・終了取得に失敗 新たなコマンドを重ねず、報告・後片付けして非0終了する案（D04）

D04では子の終了を確認したと偽りません。HANDLEを閉じても子の強制終了を意味しません。子の強制終了は本体の対象範囲へ自動追加しません。

組み込みは処理の文脈と保存済みWin32エラーをB経由で報告し、Aは同じエラーを二重表示しません。processは画面表示せず結果をAへ返し、AがBを呼びます。エラー表示自体の失敗で再帰しません。Chell独自の構文・引数エラーはconsole_write_error、保存済みWin32エラーはconsole_report_errorを使い、どちらも戻り値を確認します。これは重複表示を避けるための準備版の責任分担です。

7. 中断

Ctrl+C/対象のCtrl+Breakでは、親シェルを存続させます。入力中と子の実行中を別ケースで検証します。中断に対応する子が終了したことを確認してから次の入力へ戻ります。中断を無視する子の強制終了は対象外です。

通知イベントをconsole_read_lineへ渡すだけでは、ブロック中の読み取りを解除する実装にはなりません。A/B/Eで入力モード、読み取り解除方法、実行中ハンドラーと解放の同期を決め、通常コンソールで確認します。詳細はD02として未固定です。組み込み処理中の中断は、ハンドラーから強制的に抜けず資源を片付けます。通常完了として扱うか中断結果へ変換するかもD02で決めます。ウィンドウを閉じる操作やログオフは、Ctrl+Cと同じ存続保証には含めません。

9. D06を決めるためのAPI観測例

2026-11-17、このWindows端末でCommandLineToArgvWを直接呼び、戻った文字列を確認しました。下の入力・値はCリテラルではなく、実際の文字をそのまま記載しています。これはOS APIの観測であり、Chellの検査実装が合格した記録ではありません。

1. 図の読み方と依存方向

下の矢印は「左のファイルが右のヘッダーの宣言を使う」です。実行時のデータ移動とは別です。

console.hはstddef.hとwindows.hを自分でincludeし、共有のCommandやShellStateには依存しません。共有上限を使うconsole_input.cはshell_types.hを直接includeします。shell_types.hは上位のshell.hをincludeしません。各ヘッダーにinclude guardを付けます。

2. 共有型: shell_types.h（配置はD05の提案）

#include <stddef.h>
#include <windows.h>

enum {
    SHELL_LINE_CAPACITY = 4096,
    SHELL_ARG_LIMIT = 64
};

typedef struct {
    wchar_t *raw_line;
    int argc;
    wchar_t **argv;
} Command;

typedef struct {
    BOOL exit_requested;
    DWORD last_exit_code;
} ShellState;

Commandの空状態はraw_line=NULL、argc=0、argv=NULL。ShellStateの初期値はexit_requested=FALSE、last_exit_code=0です。

Commandはコピーして別々に解放しません。構造体代入はポインタを複製するだけで、所有メモリを複製しないためです。argvはargcで走査し、argv[argc]がNULLであることへ依存しません。

Commandの有効期間中、argvの文字列とraw_lineはCommandが所有します。呼び出し先はconst Command *で借用し、内容の変更・個別解放・呼び出し後の保存をしません。外部実行用の変更可能なコピーはprocess側が別に確保します。const Command *でも、ポインタが指す文字列までCの型だけで変更禁止になるわけではありません。変更しないことを契約として守ります。

ShellStateの生存期間をAが管理します。通常はAがlast_exit_codeを更新し、Eのexit処理がexit_requestedをTRUEにします。各コマンドが無関係な状態を書き換えないようにします。

BOOL出力APIのFALSE時には呼び出し側が直後にGetLastErrorで原因を保存できる契約を提案します（D05）。Bは後片付け前に最初のエラー値を保存し、返す直前にSetLastErrorで復元します。変換・確保失敗も非0のエラー値へ対応付けます（10節）。成功後のGetLastErrorは読みません。

LINE_OK 改行を除いた終端付き入力。空行も含む 0 Cへ渡す
LINE_CANCELLED 空文字列。途中入力を使わない 0 再入力、直前コードを維持
LINE_EOF 空文字列 0 後片付けして終了
LINE_TOO_LONG 空文字列。残りを行末まで捨てる 0 報告後に再入力

出力先がコンソールならWriteConsoleW、ファイル等ならUTF-8へ変換してWriteFileを使う方針です。全体を書き切るまで進め、成功扱いで0単位しか進まない場合も失敗へ変換します。通常出力はstdout、診断はstderr、改行はCRLF、UTF-8出力にBOMは付けない案です。エラー文の全文一致は確認条件にせず、文脈とエラー値を確認します。

出力関数は渡された文字列へ改行を自動追加しません。コマンド側が仕様どおりの改行を文字列へ含め、プロンプトや分割出力へ余分な改行を入れないようにします。

ConsoleReadResultをゼロ初期化すると、現在の宣言ではstatusがLINE_OKになります。ゼロ初期化だけを完了結果として返さず、全経路でstatusを明示します。LINE_ERROR=0へ並べ替える案はD05の代案であり、採用する場合は呼び出し側とテストも同時に合わせます。ParseResultも同様に、PARSE_OKを明示した結果だけを利用します。

ReadConsoleWはコンソールの入力用で、別イベントを引数に渡して待機を解除するAPIではありません。中断方式と入力モードの実機確認をD02から落とさないでください。公式資料

4. 解析: parser.h / C

#include "shell_types.h"

typedef enum {
    PARSE_OK,
    PARSE_EMPTY,
    PARSE_TOO_LONG,
    PARSE_TOO_MANY_ARGS,
    PARSE_INVALID_SYNTAX,
    PARSE_NO_MEMORY,
    PARSE_API_ERROR
} ParseStatus;

typedef struct {
    ParseStatus status;
    DWORD win32_error;
} ParseResult;

ParseResult parse_command(const wchar_t *line, Command *out_command);
void command_free(Command *command);

前提: lineは改行除去済み・終端付きの非NULL文字列、out_commandは非NULLの空Commandです。生きたCommandを上書きして再利用せず、先にcommand_freeします。入力lineは借用で変更しません。

  • 長さ上限は先頭空白を取り除く前の入力全体へ適用する。本文4,095単位を超えたらPARSE_TOO_LONG。
  • PARSE_OKだけが有効なCommandを返す。argcは1〜64、argv[0]は非空。
  • PARSE_EMPTYを含む成功以外の全結果は空Commandを返す。Cが途中の確保も片付ける。
  • raw_lineはmalloc系による独立コピー、argvはCommandLineToArgvWの戻り値。
  • command_freeはraw_lineをfree、argvを1回のLocalFreeで解放し、全フィールドを空状態へ戻す。空Commandへの繰り返し呼び出しを安全にする。
  • command_free(NULL)は準備版では前提外。空構造体とNULLポインタを混同しない。
  • malloc系失敗はPARSE_NO_MEMORY、CommandLineToArgvW等のAPI失敗はPARSE_API_ERROR。win32_errorはPARSE_API_ERRORだけで保存値を返し、他は0。API側のメモリ不足もここではPARSE_API_ERRORとする。後片付け前にエラー値を保存する。

CommandLineToArgvWの確保単位と解放方法は公式資料を参照します。

9. 中断APIを固定する前の確認事項: D02

Eへ共通制御の実装を配分する案を採用する場合に、interrupt.h / src/E/interrupt.cを追加します。以下の契約を先に決め、関数名・引数・構造体を後から確定します。存在しない宣言を合意済みAPIとして掲載しません。

  1. 初期化失敗を呼び出し側へ返し、部分初期化も片付ける。
  2. Aがシェルの生存期間を管理し、Bがイベントを借用する。
  3. 入力開始前のリセットと、入力中断時の読み取り解除・残入力破棄を定義する。
  4. 子の実行中は親を存続させ、子の終了確認後に入力へ戻る。
  5. 制御ハンドラー内では通知に限定し、表示・メモリ解放・組み込みを実行しない。
  6. 登録解除と実行中ハンドラーの同期を確認してからイベントを破棄する。
  7. デバッガー外の通常コンソールでCtrl+CとCtrl+Breakを確認する。

  • 配列の要素数、終端、バイト数を混同しない。
  • constは借用中の変更を抑える約束。資源の所有権や寿命そのものは別に決める。
  • APIごとに成功・失敗・エラー取得・解放関数が違う。
  • HANDLEはすべてCloseHandleでよいわけではない。
  • NULLポインタと、空フィールドを持つ構造体を分ける。

既存の担当別ハンズオンを補助に使えます。教材の小さい型・関数名を、公開APIへそのままコピーしません。教材の課題完了は本体の機能合格とは別です。

受け渡しを1枚で読む

開発担当の記号と実行スレッドは別です。通常処理はAのループから同じスレッドで呼びます。次の図の矢印は「渡すデータ」で、include依存ではありません。

担当 受け取るもの 返すもの 自分で片付けるもの
A shell 入力・解析・実行の結果 最終終了コード Commandの解放呼び出し、シェル全体の資源
B 借用buffer・capacity・文字列・イベント（D02） LINE結果、BOOL、保存エラー 表示変換やエラー文の一時領域
C 借用lineと空Commandのアドレス status、成功したCommand 途中失敗の確保、command_freeで受けた領域
D 借用CommandとShellState handled・output_failed・コード 現在位置取得用領域、列挙HANDLE
E 借用CommandとShellState 同じ結果型、exit要求 自分が一時確保した表示用領域
A process 借用Command 起動・終了確認の結果 可変コピー、解決パス、子のHANDLE

Cの宣言を具体例へ置き換える

/* 呼び出し方の説明用。完成したshell_runではありません。 */
Command command = {0};
ParseResult parsed = parse_command(L"echo \"hello world\"", &command);
/* parsed.status == PARSE_OK の場合だけcommandを利用する。 */
/* 処理を終えたら、exit要求や実行失敗でも同じ解放地点へ進む。 */
command_free(&command);

&commandは「この構造体へ書いてよい」という出力先です。command_freeの後はraw_lineとargvを参照しません。D/Eが借りている最中に解放せず、D/Eもポインタを保存して後から使いません。

手書きCommandで確認する場合、文字列リテラルやスタック上の配列をCが確保したメモリのようにcommand_freeへ渡してはいけません。借用入力の確認と、解析成功した所有Commandの解放確認を分けます。

契約をこの形にする理由（Why）

判断 その理由 担当が確認すること
Commandの作成・解放をCへ集める malloc系とLocalFreeの取り違え、失敗途中の漏れを防ぐ Aは成功後に1回解放し、Cは失敗途中を片付ける
